# AI 能力与拓展功能开发路线图

## 1. 目标

MVP 已经完成“语音输入 -> 指令解析 -> 画布执行 -> 反馈 -> PNG 导出”的核心闭环。后续开发目标是在保持主分支可运行的前提下，逐步增强绘图能力、对象管理能力和 AI 理解能力。

本路线图从远端 PR #7 合并后的 `main` 分支继续推进。本地未合并的实验性 PR 或草稿分支不作为后续开发基线。

后续所有功能仍遵循：

- 每个 PR 只做一件事。
- 每个 PR 必须包含清晰的功能描述、实现思路和测试方式。
- 主分支合并后必须可运行、可测试、可演示。
- 引入第三方库、AI 服务或复用代码时，必须在 README 或 PR 描述中说明用途与来源。
- AI 能力不得绕过结构化命令协议，所有 AI 输出必须经过校验后才能进入执行器。

## 2. 总体路线

```text
MVP 核心闭环
  -> 拓展基础能力
  -> AI 指令理解
  -> AI 创作辅助
  -> 演示与交付增强
```

## 3. 固定开发工作流

后续每个模块都按同一套流程开发，保证持续交付记录清晰、主分支稳定：

1. 从远端 `main` 拉取最新代码，确认基线来自已合并 PR。
2. 为单一模块创建新分支，分支名建议使用 `codex/` 或 `feature/` 前缀。
3. 只实现一个功能点，必要时同步更新 README、产品文档、架构文档或路线图。
4. 本地执行 `npm audit`、`npm run test`、`npm run build`。
5. 使用中文 commit 信息提交。
6. 推送分支并创建中文 PR。
7. PR 描述必须包含功能描述、实现思路、测试方式。
8. 合并后切回 `main`，拉取远端最新代码，再进入下一个模块。

后续若某个功能较大，需要先拆成“接口定义 -> mock 实现 -> UI 接入 -> 真实服务接入 -> 错误恢复”多个 PR。

## 4. 阶段一：拓展基础能力

这一阶段先增强现有规则链路和画布能力，为后续 AI 能力提供稳定的执行基础。

| 模块 | 目标 | 建议 PR 粒度 | 验证方式 |
| --- | --- | --- | --- |
| 对象命名 | 支持“把这个圆命名为开始”“移动开始节点” | 新增对象名称字段、命名指令、按名称查找 | 已进入实现模块，单元测试覆盖命名、查找、移动 |
| 对象定位 | 支持“左边那个圆”“最大的矩形” | 增加按类型、位置、尺寸查找目标 | 已进入实现模块，单元测试覆盖位置、类型和尺寸定位 |
| SVG 导出 | 支持语音导出 SVG 文件 | 在现有导出层增加 SVG 下载 | 已进入实现模块，单元测试覆盖 SVG 指令和导出请求 |
| JSON 工程文件 | 支持保存和加载画布工程 | 增加 JSON 导出、本地保存/加载、版本字段 | 当前模块已实现，单元测试覆盖工程序列化、导出请求和保存/加载状态闭环 |
| 图层顺序 | 支持置顶、置底、前移、后移 | 增加层级调整命令 | 当前模块已实现，单元测试覆盖解析、对象顺序变化和撤销恢复 |
| 模板节点 | 支持流程图节点、判断节点等基础模板 | 增加模板对象工厂 | 单元测试模板对象结构 |

阶段完成标准：

- 规则解析仍能覆盖 MVP 指令。
- 画布对象模型支持名称、层级和工程序列化。
- 导出能力至少覆盖 PNG、SVG、JSON。

## 5. 阶段二：AI 指令理解

这一阶段接入 AI 能力，但不直接让 AI 操作画布。AI 只负责把自然语言转换为结构化命令草案，执行前仍由本地校验器检查。

### 5.1 AI 解析架构

```text
用户语音文本
  -> 规则解析器
  -> 规则解析成功：直接执行
  -> 规则解析失败或置信度不足
  -> AI 解析适配器
  -> 结构化命令草案
  -> 命令校验器
  -> CommandExecutor
```

### 5.2 建议模块

| 模块 | 目标 | 建议 PR 粒度 | 验证方式 |
| --- | --- | --- | --- |
| AI 适配器接口 | 定义可替换的 AI 解析 Provider | 新增 `AiCommandProvider` 接口和 mock provider | 单元测试 mock 解析 |
| 命令 Schema 校验 | 限制 AI 只能输出合法命令 | 增加命令校验器和错误反馈 | 单元测试非法命令拒绝 |
| AI 解析开关 | 支持显式开启或关闭 AI 解析 | 增加设置状态和环境变量说明 | 单元测试开关行为 |
| AI 解析服务 | 通过后端代理或本地服务调用模型 | 新增最小后端接口，避免前端暴露密钥 | 接口测试、失败降级测试 |
| 多轮澄清 | 对缺失目标或参数进行追问 | 增加 pending question 状态 | 单元测试追问与补全 |
| 复杂指令拆解 | 把长句拆成多条结构化命令 | AI 输出命令数组，执行器顺序执行 | 单元测试复合命令计划 |

阶段完成标准：

- AI 解析失败时可以回退到规则解析或给出明确反馈。
- AI 输出必须通过 schema 校验，不允许直接执行任意代码或任意文本。
- API key 不进入前端包、不提交到仓库。
- CI 或本地测试默认使用 mock provider，不依赖真实网络调用。

## 6. 阶段三：AI 创作辅助

这一阶段让 AI 从“理解单条命令”扩展到“辅助生成和优化图示”。

| 模块 | 目标 | 建议 PR 粒度 | 验证方式 |
| --- | --- | --- | --- |
| 一句话生成图示 | 例如“生成一个用户登录流程图” | AI 生成命令计划，用户语音确认后执行 | mock 测试生成计划 |
| 自动布局优化 | 根据对象关系减少重叠、对齐节点 | 增加布局建议器和应用命令 | 单元测试布局结果 |
| 画布内容总结 | 支持“现在画布里有什么” | 将对象列表转成中文摘要 | 单元测试摘要文本 |
| 优化建议 | 支持“帮我优化这个流程图” | AI 返回建议和可执行操作列表 | mock 测试建议格式 |
| 模板生成 | 支持流程图、思维导图、组织结构图模板 | 模板计划转结构化命令 | 单元测试模板命令 |

阶段完成标准：

- 所有 AI 生成内容都能追溯为结构化命令计划。
- 用户可以通过语音确认、取消或撤销 AI 生成结果。
- 大型生成操作写入历史记录，支持一次性撤销。

## 7. 阶段四：演示与交付增强

这一阶段服务于最终提交、答辩和仓库长期可维护性。

| 模块 | 目标 | 建议 PR 粒度 | 验证方式 |
| --- | --- | --- | --- |
| Demo 脚本 | 固化演示语音指令顺序 | 增加 demo 文档和 README 链接占位 | 人工演示检查 |
| 浏览器兼容说明 | 明确 Chrome、Edge、HTTPS 限制 | 更新 README 与架构文档 | 文档检查 |
| 错误恢复体验 | 麦克风失败、AI 超时、导出失败的友好提示 | 增加错误状态和反馈文案 | 单元测试错误路径 |
| 自动化测试补强 | 增加更多 command fixture | 扩充 Vitest 用例 | `npm run test` |
| Demo 视频链接 | 录制并补充视频地址 | 更新 README | 链接可访问 |

阶段完成标准：

- README 中包含可播放的 demo 视频链接。
- 评委可以按 README 步骤复现核心演示。
- 项目依赖、原创功能、AI 接入边界说明完整。

## 8. 推荐开发顺序

阶段一已完成对象命名、对象定位、SVG 导出、JSON 工程保存/加载和图层顺序调整。后续建议按照以下顺序推进：

1. AI 适配器接口与 mock provider
2. 命令 schema 校验
3. AI 解析服务接入
4. 多轮澄清和复杂指令拆解
5. 一句话生成图示
6. 画布总结与优化建议
7. Demo 脚本和视频链接

如果时间紧，优先完成 1 到 4。这样可以展示“规则能力 + AI 理解能力 + 安全校验闭环”，比堆很多零散画布功能更有说服力。

## 9. 每个 PR 的最低交付要求

每个后续 PR 至少包含：

- 一个明确功能点。
- 对应代码或文档变更。
- 必要测试或人工验证说明。
- README 或相关文档更新。
- 中文 commit 信息。
- 中文 PR 标题和描述。

合并前必须执行：

```bash
npm audit
npm run test
npm run build
```

如果某个 PR 只修改文档，仍建议执行 `npm run test` 和 `npm run build`，确认主分支没有被已有问题影响。

## 10. AI 能力约束

后续接入 AI 时必须遵守以下边界：

- AI 只生成结构化命令或命令计划，不直接操作 DOM、Canvas 或应用状态。
- 所有 AI 输出必须通过 allow-list schema 校验。
- 模型调用失败、超时或返回非法结构时，系统需要给出语音或文本反馈。
- 默认保留本地规则解析作为低延迟路径。
- 涉及 API key 时必须通过环境变量或后端代理注入，不得提交密钥。
- 测试环境使用 mock provider，避免测试依赖真实 AI 服务。

## 11. 风险控制

| 风险 | 应对 |
| --- | --- |
| AI 输出不可控 | 使用 schema 校验、命令白名单、失败回退 |
| 响应延迟变高 | 规则优先、AI 仅处理复杂或失败指令、设置超时 |
| 费用或配额不稳定 | 支持关闭 AI、mock 演示、错误提示 |
| 语音误识别导致错误执行 | 高风险操作先确认，例如清空、批量生成、覆盖导入 |
| 功能范围膨胀 | 每个 PR 只做一个功能，按路线图推进 |
