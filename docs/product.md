# AI 语音绘图工具产品文档

## 1. 产品定位

AI 语音绘图工具是一款完全通过语音完成绘图创作的应用。用户不使用鼠标和键盘，通过自然语言指令完成画布创建、图形绘制、样式调整、对象编辑、撤销重做和作品导出。

产品核心价值：

- 降低绘图操作门槛，让用户用自然语言表达创作意图。
- 验证纯语音交互在图形创作场景中的可行性。
- 展示语音识别、指令理解、上下文管理和画布操作调度的综合能力。

## 2. 目标用户

- 需要快速绘制简单图示、草图、流程关系图的普通用户。
- 希望用自然语言进行创作探索的用户。
- 不方便使用鼠标或键盘，但仍需要完成基础图形创作的用户。
- 课程或演示场景中需要展示 AI 语音交互能力的开发者。

## 3. 核心使用场景

### 3.1 语音创建图形

用户说：“画一个红色圆形。”

系统识别语音内容，解析图形类型、颜色和默认位置，在画布中创建对应对象，并反馈“已创建红色圆形”。

### 3.2 语音编辑对象

用户说：“把它变大一点。”

系统基于上下文找到最近创建或当前选中的对象，执行缩放操作，并反馈编辑结果。

用户也可以说：“把它置顶”“把左边那个圆上移一层”。系统会调整对象在 SVG 渲染顺序中的位置，让指定对象显示在更上层或更下层。

### 3.3 语音执行复合指令

用户说：“在圆形右边画一个蓝色矩形，并用箭头连接它们。”

系统将指令拆解为：

1. 定位圆形对象
2. 创建蓝色矩形
3. 计算矩形相对位置
4. 创建连接箭头

### 3.4 语音导出作品和工程

用户说：“导出为图片。”

系统将当前画布导出为图片文件，并提示导出结果。

用户也可以说：“导出为 JSON”“保存工程”“加载工程”。系统会导出可再次编辑的工程文件，或在浏览器本地保存和恢复最近一次工程快照。

## 4. MVP 范围

MVP 目标是完成一条可演示、可闭环的纯语音绘图流程：用户说话，系统理解，画布变化，系统反馈。

当前 MVP 核心闭环已实现，待用户本地验证和录制 demo 视频。

### 4.1 MVP 必须实现

#### 语音输入

- 支持浏览器麦克风录音授权
- 支持中文语音识别
- 支持显示最近一次识别文本
- 支持语音识别失败提示
- 支持操作结果语音播报

#### 基础绘图

- 创建圆形、矩形、直线、箭头、文本
- 设置基础颜色，例如红、蓝、绿、黄、黑、白
- 设置基础尺寸，例如大、小、变大、变小
- 支持常见位置，例如中间、左边、右边、上方、下方、左上角、右下角

#### 基础编辑

- 移动对象：向上、向下、向左、向右
- 删除对象
- 修改颜色
- 修改大小
- 调整层级：置顶、置底、上移一层、下移一层
- 撤销与重做
- 清空画布

#### 上下文引用

- 支持“它”“刚才那个”“这个图形”等指代
- 默认将最近创建或最近编辑的对象作为当前对象

#### 反馈机制

- 成功时给出简短反馈
- 指令无法理解时提示用户重新表达
- 关键信息缺失时主动追问

#### 导出

- 支持导出 PNG 图片
- 拓展阶段已支持导出 SVG 文件
- 拓展阶段已支持导出 JSON 工程文件
- 拓展阶段已支持浏览器本地工程保存与加载

### 4.2 MVP 暂不实现

- 复杂自由曲线绘制
- 多人协作
- 长文档式图形编辑
- 高精度自动排版
- 跨设备云端同步
- 完整账号系统
- 复杂 AI 生成图片能力

这些能力会放入后续拓展阶段，避免 MVP 范围过大影响核心链路交付。

## 6. 后续拓展功能

后续拓展功能按照 [`ai-expansion-roadmap.md`](ai-expansion-roadmap.md) 分阶段开发。优先保证每个阶段都能独立演示、独立测试、独立 PR 合并。

### 6.1 指令理解增强

- 支持更自然的口语表达
- 支持更复杂的复合指令拆解
- 支持多轮确认和追问
- 支持用户自定义常用指令
- 支持指令执行前预览和确认

### 6.2 绘图能力增强

- 支持自由曲线、钢笔路径和手绘风格
- 支持更多图形库，例如流程图节点、思维导图节点、图标
- 支持自动对齐、等距分布、组合和取消组合
- 已支持对象命名、对象定位和语音层级顺序调整
- 后续支持图层面板和对象树
- 支持模板，例如流程图、组织结构图、课堂板书

### 6.3 AI 辅助创作

- 已建立可替换的 AI 指令解析 Provider 接口
- 已提供本地 mock provider，用于演示复杂指令生成结构化命令草案
- 已提供命令 schema 校验，AI 输出必须通过 allow-list 才能进入后续执行链路
- 已提供 HTTP AI provider，前端通过 `VITE_AI_COMMAND_ENDPOINT` 调用后端代理或本地服务，不在前端保存模型 API key
- 已提供 AI command planner，用于保存澄清问题、合并用户补充回答并组织复杂命令计划
- 已提供 AI 解析开关、语音开关指令和语音确认执行入口
- 已支持根据一句话自动生成图示草稿，当前覆盖登录、注册、订单支付、客服工单、审批和项目发布等流程图模板
- 根据画布内容给出优化建议
- 自动整理杂乱图形布局
- 自动生成流程图或思维导图
- 支持从文本段落提取图形结构

### 6.4 多模态反馈

- 支持语音播报操作结果
- 支持高亮最近操作对象
- 支持操作历史回放
- 支持无障碍模式，例如更高对比度和更强语音提示

### 6.5 保存与协作

- 已支持导出 SVG 文件
- 已支持导出 JSON 工程文件
- 已支持浏览器本地保存工程并再次编辑
- 后续支持导出 PDF
- 支持历史版本管理
- 支持云端存储
- 支持多人协作和共享链接

### 6.6 拓展开发优先级

| 阶段 | 重点能力 | 用户价值 |
| --- | --- | --- |
| 阶段一：拓展基础能力 | 对象命名、对象定位、SVG 导出、JSON 保存、图层顺序 | 让语音编辑更精确，作品可以保存和再次编辑 |
| 阶段二：AI 指令理解 | AI 解析接口、命令校验、AI 服务接入、多轮澄清 | 让系统理解更自然、更复杂的表达 |
| 阶段三：AI 创作辅助 | 一句话生成图示、自动布局、画布总结、优化建议 | 从“执行命令”升级为“辅助创作” |
| 阶段四：演示与交付增强 | Demo 脚本、错误恢复、兼容说明、视频链接 | 提高最终提交和评审复现质量 |

当前已完成阶段一基础拓展能力，并已进入阶段二 AI 指令理解和阶段三 AI 创作辅助。现阶段已实现 AI 适配器接口、mock provider、命令 schema 校验、HTTP AI provider、AI command planner、AI 解析开关、前端执行入口和一句话生成图示模板。真实模型调用需要由后端代理承接，前端只发送语音文本和必要画布上下文，不会让 AI 输出绕过 allow-list 校验直接执行。

用户可以先说“把它命名为开始节点”，后续再说“移动开始节点向右”；也可以说“把左边那个圆改成绿色”“移动最大的矩形向右”“把左边那个圆置顶”“保存工程”“加载工程”或“导出为 JSON”。

最小 AI 展示闭环为：

```text
用户说复杂绘图需求
  -> 规则解析无法覆盖
  -> 已开启 AI 解析
  -> AI 生成结构化命令计划
  -> 缺少目标或参数时追问用户
  -> 本地 schema 校验
  -> 用户语音确认
  -> 执行并支持撤销
```

## 7. 成功指标

MVP 阶段重点关注以下指标：

- 常见单步指令识别和执行成功率达到可演示水平
- 简单指令从语音结束到画布更新的延迟控制在 1 秒左右
- 复合指令能够被拆解并顺序执行
- 用户不使用鼠标键盘也能完成完整作品创建和导出
- 无法理解指令时，系统能够给出清晰反馈

## 8. 风险与应对

| 风险 | 影响 | 应对策略 |
| --- | --- | --- |
| 浏览器语音识别不稳定 | 指令无法准确输入 | 保留识别文本展示与错误反馈 |
| 中文自然语言表达多样 | 解析准确率下降 | MVP 先覆盖高频规则，后续接入语义解析 |
| 复合指令拆解复杂 | 执行结果不可控 | 限制 MVP 复合指令范围，逐步扩展 |
| 纯语音选择对象困难 | 编辑目标不明确 | 使用最近对象、对象类型和位置描述共同定位 |
| 延迟过高 | 影响操作体验 | 本地规则优先，复杂语义解析异步处理 |
| AI 输出不稳定 | 可能生成非法或危险操作 | 使用命令 schema 校验、白名单和失败回退 |
| API key 泄漏 | 造成安全和费用风险 | 通过后端代理或服务端环境变量管理，不提交密钥，也不打包进前端 |
