# AI 语音绘图工具

## 项目简介

本项目对应选题二：开发一款纯语音控制的绘图工具。用户不能使用鼠标或键盘，只能通过语音指令完成绘图创作、图形编辑、画布操作、样式调整和作品导出等流程。

项目重点不只是“能听懂命令”，还需要综合考虑：

- 语音指令理解的准确性与容错性
- 语音到绘图操作的响应延迟
- 复杂指令的拆解与执行能力
- 无鼠标、无键盘场景下的交互闭环
- 已实现能力、未实现能力与原因说明

## 当前 MVP 状态

当前已完成 MVP 核心闭环：

```text
语音输入
  -> 中文语音识别
  -> 指令解析
  -> 命令执行
  -> SVG 画布渲染
  -> 反馈展示与语音播报
  -> PNG/SVG/JSON 导出与本地工程保存
```

已实现能力：

- 中文语音识别入口，支持临时识别文本和最终识别文本展示
- 纯语音触发绘图命令，不提供鼠标绘图入口
- 创建圆形、矩形、直线、箭头和文本
- 设置基础颜色、位置和大小
- 修改当前对象颜色、放大、缩小、移动和删除
- 调整对象层级顺序
- 撤销、重做、清空画布
- 简单复合指令，例如“画两个圆，并用箭头连接它们”
- PNG 图片、SVG 文件和 JSON 工程文件导出
- 本地工程保存与加载
- 操作结果文字反馈和语音播报
- 单元测试覆盖指令解析、画布执行、状态闭环和导出序列化

当前拓展进度：

- 对象命名：支持“把它命名为开始节点”
- 按名称引用：支持“移动开始节点向右”“把开始节点改成绿色”“删除开始节点”
- 对象定位：支持“把左边那个圆改成绿色”“移动最大的矩形向右”“删除右边的圆”
- SVG 导出：支持“导出为 SVG”“保存为矢量图”
- JSON 工程保存与加载：支持“保存工程”“加载工程”“导出为 JSON”“导出工程文件”
- 图层顺序：支持“把它置顶”“把开始节点置底”“把左边那个圆上移一层”
- AI 适配器接口：已提供 `AiCommandProvider` 协议和本地 mock provider，用于后续接入 AI 指令理解
- AI 命令 schema 校验：已提供 `validateDrawingCommands`，对 AI 命令草案做 allow-list 校验和字段清洗
- AI 解析服务接入：已提供 `HttpAiCommandProvider`，前端通过 `VITE_AI_COMMAND_ENDPOINT` 调用后端代理，返回命令仍必须通过 schema 校验
- AI 多轮澄清与命令计划：已提供 `AiCommandPlanner`，可在缺少目标对象时保存追问状态，并在用户补充后生成复杂命令计划
- AI 解析开关与前端执行入口：侧栏可开启 AI 解析，规则无法覆盖的语音会进入 AI planner，并要求语音确认后执行
- 一句话生成图示：mock provider 支持登录、注册、订单支付、客服工单、审批和项目发布等流程图模板

## 目标用户与使用场景

目标用户包括希望通过自然语言快速创作草图、图示、流程图或简单插画的人群，也包括不方便使用传统输入设备的用户。

典型场景：

- 通过语音创建基础图形，例如圆形、矩形、线条、箭头
- 通过语音调整颜色、大小、位置、层级和透明度
- 通过语音组合多个简单操作，完成复杂图形创作
- 通过语音撤销、重做、清空画布、保存或导出作品
- 通过语音询问当前画布状态或选中对象信息

## 核心约束

- 用户不能使用鼠标。
- 用户不能使用键盘。
- 所有绘图操作必须由语音指令触发。
- 系统应对口语化表达、模糊描述和局部识别错误具备一定容错能力。
- 系统应在无法理解命令时给出明确反馈，并引导用户重新表达。

## 技术方案

当前 MVP 采用 Web 前端单页应用实现：

```text
语音输入
  -> 语音识别
  -> 指令理解
  -> 指令规范化
  -> 绘图操作调度
  -> 画布渲染
  -> 反馈与状态更新
```

### 推荐模块划分

- `SpeechInput`：负责录音、语音识别和识别结果回调
- `CommandParser`：负责将自然语言解析为结构化指令
- `CommandExecutor`：负责执行绘图、编辑、撤销、导出等操作
- `CanvasEngine`：负责画布对象管理与渲染
- `StateManager`：负责历史记录、当前选中对象和上下文引用
- `FeedbackManager`：负责错误提示、确认反馈和状态播报

## 指令理解设计

为了提高准确性与容错性，指令理解可分为两层：

1. 规则解析：优先处理高频、明确、可枚举的绘图命令。
2. 语义解析：处理更口语化、复杂或上下文相关的表达。

结构化指令示例：

```json
{
  "action": "create",
  "shape": "circle",
  "style": {
    "fill": "red",
    "stroke": "black"
  },
  "position": {
    "region": "center"
  }
}
```

## 响应延迟目标

- 简单指令：尽量在 1 秒内完成解析与绘制
- 复合指令：尽量在 2 到 3 秒内完成拆解与执行
- 无法识别的指令：及时反馈原因，避免用户长时间等待

## 容错策略

- 支持同义词，例如“圆”“圆形”“画个圈”
- 支持模糊程度词，例如“一点”“大一些”“靠右一点”
- 支持上下文代词，例如“它”“刚才那个”“这个图形”
- 当关键信息缺失时主动追问，例如“你想画什么颜色？”
- 当识别结果置信度较低时请求用户确认

## 本地运行

安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

构建生产版本：

```bash
npm run build
```

运行测试：

```bash
npm run test
```

AI 解析服务配置：

```bash
VITE_AI_COMMAND_ENDPOINT=/api/ai/commands npm run dev
```

`VITE_AI_COMMAND_ENDPOINT` 应指向后端代理或本地服务。前端不会保存或打包模型 API key；服务端返回的数据也必须是合法命令数组，前端会再次通过 `validateDrawingCommands` 校验后才允许进入后续执行链路。

未配置 `VITE_AI_COMMAND_ENDPOINT` 时，前端 AI 开关默认使用本地 mock provider，便于演示“生成用户登录流程图”“高亮这个图形”等 AI 命令计划；配置 endpoint 后会切换到 HTTP provider。
